# DB設計書

## 1. はじめに
本書はtms-appのデータベース設計を記述する。DB製品はPostgreSQLを使用し、一部PostgreSQL固有機能（部分UNIQUEインデックス、CHECK制約）に依存する。ソフトデリートは全テーブルで未使用（物理削除のみ）。多対多の中間テーブルは存在しない。

## 3. テーブル定義書

### 3.1 業務テーブル

#### `departments`（部署マスタ）
| カラム | 型 | NULL | デフォルト | 制約 |
|---|---|---|---|---|
| id | bigint unsigned | NO | auto increment | PK |
| name | varchar(255) | NO | - | - |
| code | varchar(255) | NO | - | UNIQUE |
| created_at / updated_at | timestamp | YES | null | - |

配属履歴（`employee_assignments.department_id`）、または研修の閲覧対象部署（`trainings.audience_department_id`）で使用中の部署は削除できない（アプリ側のガード、`PositionInUseException`と同様のパターンで`DepartmentInUseException`を使用）。

#### `positions`（役職マスタ）
| カラム | 型 | NULL | デフォルト | 制約 |
|---|---|---|---|---|
| id | bigint unsigned | NO | auto increment | PK |
| name | varchar(255) | NO | - | - |
| code | varchar(255) | NO | - | UNIQUE |
| rank | smallint unsigned | NO | 0 | コメント: 「役職の序列（数値が小さいほど上位）。昇格・降格の比較や表示順に利用する。」 |
| created_at / updated_at | timestamp | YES | null | - |

#### `employees`（従業員）
| カラム | 型 | NULL | デフォルト | 制約 |
|---|---|---|---|---|
| id | bigint unsigned | NO | auto increment | PK |
| user_id | bigint unsigned | NO | - | UNIQUE, FK→users.id（cascadeOnDelete） |
| employee_code | varchar(255) | NO | - | UNIQUE（社員番号） |
| role | varchar(255) | NO | 'employee' | コメント: 「employee: 一般社員／hr: 人事（全権限）。『上司』はロールではなくemployee_assignments.manager_idから導出。」Enum値: employee, hr |
| hired_at | date | NO | - | 入社日 |
| retired_at | date | YES | null | 退職日 |
| created_at / updated_at | timestamp | YES | null | - |

#### `employee_assignments`（部署・役職・上司の割当履歴）
`ended_at IS NULL`の行が「現在の状態」を表す履歴（SCD Type 2的）テーブル。

| カラム | 型 | NULL | デフォルト | 制約 |
|---|---|---|---|---|
| id | bigint unsigned | NO | auto increment | PK |
| employee_id | bigint unsigned | NO | - | FK→employees.id（cascadeOnDelete） |
| department_id | bigint unsigned | NO | - | FK→departments.id（restrictOnDelete） |
| position_id | bigint unsigned | NO | - | FK→positions.id（restrictOnDelete） |
| manager_id | bigint unsigned | YES | null | FK→employees.id（自己参照, nullOnDelete） |
| started_at | date | NO | - | - |
| ended_at | date | YES | null | NULL=現在有効 |
| created_at / updated_at | timestamp | YES | null | - |

インデックス:
- 複合index `(employee_id, started_at)`
- 複合index `(manager_id, ended_at)`
- 部分UNIQUEインデックス `employee_assignments_one_active_per_employee`: `UNIQUE (employee_id) WHERE ended_at IS NULL` — 1従業員につき「現在有効な割当」は同時に1件のみ

CHECK制約:
- `employee_assignments_period_valid`: `ended_at IS NULL OR ended_at >= started_at`

#### `delegations`（上司権限の一時委任）
| カラム | 型 | NULL | デフォルト | 制約 |

| delegator_id | bigint unsigned | NO | - | FK→employees.id（委任元, cascadeOnDelete） |
| delegate_id | bigint unsigned | NO | - | FK→employees.id（委任先, cascadeOnDelete） |
| started_at | date | NO | - | - |
| ended_at | date | YES | null | - |

インデックス: 複合index `(delegate_id, ended_at)`、複合index `(delegator_id, ended_at)`

#### `trainings`（研修マスタ）
| カラム | 型 | NULL | デフォルト | 制約 |
|---|---|---|---|---|
| id | bigint unsigned | NO | auto increment | PK |
| title | varchar(255) | NO | - | - |
| description | text | YES | null | - |
| category | varchar(255) | YES | null | - |
| unit_cost | decimal(10,2) | YES | null | 受講者1名あたりの費用。未設定は予算消費・ROI算出の対象外（4.7/4.8参照） |
| is_active | boolean | NO | true | - |
| audience_department_id | bigint unsigned | YES | null | FK→departments.id（nullOnDelete）。閲覧対象部署（4.5参照） |
| audience_managers_only | boolean | NO | false | 管理職のみを対象に含めるか |
| audience_new_hires_only | boolean | NO | false | 新入社員（今年度入社）のみを対象に含めるか |
| requires_multistage_approval | boolean | NO | false | 多段階承認が必要か（4.6参照） |
| approval_stage_count | tinyint unsigned | YES | null | 必要な承認段階数（2〜5。requires_multistage_approval=trueの場合のみ意味を持つ） |
| created_at / updated_at | timestamp | YES | null | - |

閲覧対象者の3条件（`audience_department_id`/`audience_managers_only`/`audience_new_hires_only`）はOR条件。いずれも未設定なら全員に公開される。`requires_multistage_approval`が true の場合、`audience_managers_only`の値に関わらず常に管理職に公開される（詳細設計書 3.7参照）。

| カラム | 型 | NULL | デフォルト | 制約 |

| id | bigint unsigned | NO | auto increment | PK |

#### `training_enrollments`（研修受講記録）
| カラム | 型 | NULL | デフォルト | 制約 |
|---|---|---|---|---|
| id | bigint unsigned | NO | auto increment | PK |
| employee_id | bigint unsigned | NO | - | FK→employees.id（cascadeOnDelete）, 複合UNIQUE(下記) |
| training_id | bigint unsigned | NO | - | FK→trainings.id（cascadeOnDelete）, 複合UNIQUE(下記) |
| status | varchar(255) | NO | 'not_started' | Enum値: not_started, in_progress, completed |
| progress | tinyint unsigned | NO | 0 | CHECK制約あり |
| due_at | date | YES | null | 受講期限 |
| started_at | timestamp | YES | null | - |
| completed_at | timestamp | YES | null | - |
| created_at / updated_at | timestamp | YES | null | - |

インデックス/制約:
- 複合UNIQUE `(employee_id, training_id)`（同一従業員×同一研修の受講記録は1件のみ）
- CHECK制約 `training_enrollments_progress_range`: `progress BETWEEN 0 AND 100`

進捗率は全体進捗率（0〜100）。Lessonが定義された研修は完了レッスンの集計から自動算出、Lesson未定義の研修のみ手動更新を許可する（詳細設計書 3.8参照）。

| employee_id | bigint unsigned | NO | - | FK→employees.id（申請対象, cascadeOnDelete） |

### 3.2 認証・システム基盤テーブル（Laravel標準）

| テーブル | 用途 |
|---|---|
| users | 認証ユーザー（1:1で`employees`と対応） |
| password_reset_tokens | パスワードリセット・招待トークン |
| sessions | セッションストア |
| cache / cache_locks | キャッシュストア |
| jobs / job_batches / failed_jobs | キューワーカー（通知の非同期送信に使用） |
| personal_access_tokens | Sanctum APIトークン（`tokenable`ポリモーフィック、現状`User`のみが対象） |

これらはLaravelフレームワーク標準のテーブルであり、対応するアプリ固有のEloquentモデルは持たない（`users`のみ独自モデルを持つ）。

## 5. クエリスコープ（データ絞り込み）
